Глава 47: Операционные системы и виртуализация

Операционная система (ОС) — системное программное обеспечение, управляющее ресурсами компьютера и предоставляющее интерфейс для приложений. Виртуализация — абстрагирование аппаратных ресурсов для создания виртуальных копий.

1. Управление процессами

Процесс vs поток

Процесс

Изолированное выполнение: свой адресное пространство, PCB (Process Control Block), таблица страниц.

Поток

Легковесный процесс: общее адресное пространство, собственный стек, регистры, program counter.

Утверждение 1: Алгоритмы планирования

Сравнение алгоритмов планирования процессов:

АлгоритмСложностьStarvationPreemption
FIFO$O(1)$Convoy effectНет
SJF$O(n \log n)$Да (длинные)Optional
Round Robin$O(1)$НетДа
MLFQ$O(1)$МинимальноДа
CFS (Linux)$O(\log n)$НетДа

Утверждение: Для $n$ процессов с bursts $b_1 \leq b_2 \leq \ldots \leq b_n$ среднее время ожидания при SJF:

$$\bar{W}_{\text{SJF}} = \frac{1}{n} \sum_{i=1}^{n} \sum_{j=1}^{i-1} b_j$$

SJF оптимален по среднему времени ожидания (доказательство обменом).

Состояния процесса

Множество состояний процесса — конечный автомат:

$$\text{New} \to \text{Ready} \rightleftharpoons \text{Running} \to \text{Terminated}$$
$$\text{Running} \to \text{Blocked (I/O)} \to \text{Ready}$$

Утверждение 2: Мьютексы и взаимная блокировка

Условия взаимной блокировки ( Coffman conditions ):

  1. Взаимное исключение — ресурс используется эксклюзивно
  2. Удержание и ожидание — процесс держит ресурс, ожидая другой
  3. Отсутствие принудительного изъятия — ресурс нельзя отобрать
  4. Циклическое ожидание — цикл в графе зависимостей

Доказательство: Если все 4 условия выполняются одновременно, то граф ожидания $G = (V, E)$ содержит цикл, и ни один процесс не может завершить. Следовательно, deadlock неизбежен.

$$\text{Deadlock} \iff \text{cycle in wait-for graph} \iff \text{all 4 conditions hold}$$

2. Управление памятью

Виртуальная память

Утверждение 3: Таблица страниц

Виртуальная память разбивает адресное пространство на страницы фиксированного размера $2^k$:

$$\text{virtual address} = \underbrace{p}_{\text{page number}} \| \underbrace{d}_{\text{offset}}$$

Для 64-бит адреса, страниц 4 КБ ($k=12$): $p$ = 52 бит, $d$ = 12 бит. Число страниц: $2^{52} \approx 4.5 \times 10^{15}$.

Алгоритмы замены страниц

Утверждение 4: Аппарат Беллди (Belady's Anomaly)

Для алгоритма FIFO увеличение числа фреймов может увеличить число page faults:

$$m < n \implies PF_m \geq PF_n \quad \text{(не всегда для FIFO)}$$

Доказательство: Строка обращений 1,2,3,4,1,2,5,1,2,3,4,5. При 3 фреймах: 9 faults. При 4 фреймах: 10 faults. Для LRU и Optimal аномалии нет (monotonically decreasing).

LRU$O(1)$ (стек)Нет~Оптимален
FIFO$O(1)$ДаНе оптимален
Second Chance$O(1)$НетПриближение LRU

Утверждение 5: Working Set Model

Рабочий набор — множество страниц, используемых в окне времени $\Delta$:

$$W(t, \Delta) = \{ p \mid p \text{ accessed in } [t - \Delta, t] \}$$

Если физическая память $M \geq |W(t, \Delta)|$ для всех процессов, thrashing отсутствует. Если $M < \sum |W_i|$, система «тормозит» (thrashing).

3. Файловые системы

Структура файловой системы

Файловая система организует данные на диске:

$$\text{Superblock} \to \text{Inode bitmap} \to \text{Inodes} \to \text{Data blocks}$$

Утверждение 6: Inode и ссылки

Inode — структура данных, содержащая метаданные файла (без имени):

  • Размер файла, права доступа, timestamps
  • Указатели на данные: 12 прямых + 1 косвенный + 1 двойной косвенный
  • Счётчик ссылок (hard links)

Максимальный размер файла при 4 КБ блоках и 32-бит указателях:

$$S_{\max} = (12 + \frac{4096}{4} + \frac{4096^2}{4^2}) \cdot 4096 \approx 16 \text{ ТБ}$$

4. Виртуализация

Уровни виртуализации

Type 1 (Bare-metal)

ESXi, Xen, KVM. Гипервизор работает напрямую на железе. Максимальная производительность.

Type 2 (Hosted)

VirtualBox, VMware Workstation. Гипервизор запускается как приложение ОС. Удобство.

Hardware-assisted

Intel VT-x, AMD-V. Расширения CPU для виртуализации. Устранение binary translation.

Para-virtualization

Hyper-V, Xen PV. Гость «знает» о виртуализации. Оптимизация гипервизорных вызовов.

Утверждение 7: Overhead виртуализации

Производительность виртуальной машины относительно bare-metal:

$$\text{Performance}_{VM} = \text{Performance}_{bare} \cdot (1 - \epsilon_{\text{CPU}} - \epsilon_{\text{I/O}} - \epsilon_{\text{mem}})$$

где $\epsilon_{\text{CPU}} \approx 2\text{–}5\%$ (hardware-assisted), $\epsilon_{\text{I/O}} \approx 5\text{–}15\%$, $\epsilon_{\text{mem}} \approx 1\text{–}3\%$. Типичный overhead: 5–10% для CPU-bound, 10–20% для I/O-bound.

Hardware-assisted Virtualization

Intel VT-x / AMD-V добавляют два режима:

  • VMX root mode — гипервизор (Ring -1)
  • VMX non-root mode — гость (Ring 0–3, но с ограничениями)

EPT/NPT (Extended Page Tables) — двухуровневая трансляция:

$$\text{GPA} \xrightarrow{\text{EPT}} \text{HPA} \xrightarrow{\text{page table}} \text{physical}$$

Утверждение 8: Namespace и cgroups

Linux namespaces — изоляция ресурсов:

  • PID — изоляция процессов
  • NET — изоляция сети (eth0, iptables)
  • MNT — изоляция файловых систем
  • UTS — изоляция hostname
  • IPC — изоляция межпроцессного взаимодействия
  • USER — изоляция UID/GID

cgroups — контроль ресурсов:

$$\text{cgroup} = \text{CPU quota} + \text{memory limit} + \text{I/O weight} + \text{PIDs limit}$$

Docker и Kubernetes

Docker — платформа контейнеризации (images → containers → registries).

Kubernetes — оркестрация контейнеров:

$$\text{Pod} \subset \text{Node} \subset \text{Cluster} \subset \text{Namespace}$$
  • Pod — минимальная единица деплоя (1+ контейнеров)
  • Node — физический/виртуальный сервер
  • Cluster — группа нод
  • Deployment, Service, Ingress — абстракции

6. Облачные вычисления

Модели сервисов

IaaS

Виртуальные серверы, хранилище, сети. AWS EC2, Azure VM.

PaaS

Платформа для приложений. Heroku, Google App Engine.

SaaS

Готовое приложение. Gmail, Salesforce, Dropbox.

FaaS

Serverless функции. AWS Lambda, Cloudflare Workers.

Утверждение 9: Формула стоимости облака

Стоимость $C$ в облаке vs on-premise:

$$C_{\text{cloud}}(t) = C_{\text{compute}} \cdot t + C_{\text{storage}} \cdot V + C_{\text{transfer}} \cdot D$$
$$C_{\text{on-prem}}(t) = \frac{C_{\text{hardware}}}{T_{\text{life}}} + C_{\text{power}} + C_{\text{admin}}$$

Break-even: $C_{\text{cloud}} = C_{\text{on-prem}}$ при $t \approx 3$ года для типичных нагрузок. Облако выгоднее для переменных нагрузок; on-premise — для постоянных.

Serverless вычисления

Ключевые особенности FaaS:

  • Auto-scaling: от 0 до $10^6$ инстансов
  • Pay-per-use: оплата за миллисекунды выполнения
  • Cold start: задержка инициализации 100 мс–10 с
  • Duration limit: макс. 15 мин (AWS Lambda)

7. Безопасность ОС

Модель защиты

Утверждение 10: Кольца защиты

Модель защиты Intel x86:

  • Ring 0 — ядро ОС (полный доступ)
  • Ring 1–2 — драйверы (редко используется)
  • Ring 3 — пользовательские приложения (ограниченный доступ)

System call — переход из Ring 3 в Ring 0 через инструкцию syscall. Overhead: ~100 нс на вызов.

$$T_{\text{syscall}} = T_{\text{context switch}} + T_{\text{validation}} + T_{\text{execution}}$$

ASLR и DEP

ASLR (Address Space Layout Randomization) — случайное размещение стека, кучи и библиотек:

$$\text{Entropy}_{ASLR} = \log_2(\text{positions}) \approx 20\text{–}30 \text{ бит}$$

DEP/NX (Data Execution Prevention) — запрет выполнения данных как кода. Комбинация ASLR + DEP + stack canaries = modern exploit mitigation.
