Глава 46: Компьютерные сети и интернет

Компьютерные сети — система из узлов и каналов связи, обеспечивающая обмен данными. Интернет — глобальная компьютерная сеть, использующая протокол TCP/IP для маршрутизации трафика.

Утверждение 1: Формула пропускной способности

Закон Шеннона — максимальная пропускная способность канала с шумом:

$$C = B \cdot \log_2\!\left(1 + \frac{S}{N}\right) \quad [\text{бит/с}]$$

где $B$ — полоса пропускания (Гц), $S/N$ — отношение сигнал/шум. Для Wi-Fi 6 ($B = 160$ МГц, $S/N = 30$ дБ): $C = 160 \times 10^6 \cdot \log_2(1 + 1000) \approx 1.6$ Гбит/с.

TCP: надёжная доставка

Утверждение 2: Алгоритм TCP Congestion Window

TCP использует алгоритм контроля перегрузки (Reno/CUBIC). Пропускная способность TCP:

$$\text{throughput} \leq \frac{MSS}{RTT} \cdot \frac{C}{\sqrt{p}}$$

где $MSS$ — размер сегмента, $RTT$ — время кругового обхода, $p$ — вероятность потери пакета, $C \approx 1.22$. Формула Mathis: при $p = 0.01$, $MSS = 1460$ байт, $RTT = 100$ мс: throughput $\approx 178$ Мбит/с.

Трёхстороннее рукопожатие TCP

Client → Server:  SYN  (seq=x)
Server → Client:  SYN-ACK  (seq=y, ack=x+1)
Client → Server:  ACK  (ack=y+1)
--- соединение установлено ---

Задержка установления соединения: $T_{\text{handshake}} = 2 \cdot RTT$. Для QUIC (UDP-based): $T_{\text{QUIC}} = 1 \cdot RTT$ (0-RTT при повторном подключении).

Утверждение 3: Модель HTTP-запроса

Время загрузки страницы $T$ при $N$ ресурсах:

$$T_{\text{HTTP/1.1}} = T_{\text{DNS}} + T_{\text{TCP}} + \sum_{i=1}^{N} (T_{\text{req},i} + T_{\text{trans},i})$$
$$T_{\text{HTTP/2}} = T_{\text{DNS}} + T_{\text{TCP}} + \max_i(T_{\text{req},i} + T_{\text{trans},i}) + (N-1) \cdot T_{\text{overhead}}$$

HTTP/2 даёт ускорение $T_{1.1}/T_{2} \approx N$ для большого числа мелких ресурсов.

REST API и GraphQL

REST

GET/POST/PUT/DELETE. Много запросов для одной страницы. Mature ecosystem.

GraphQL

Один запрос — все данные. Типизированная схема. Нет over-fetching.

gRPC

Protocol Buffers + HTTP/2. Высокая производительность. Streaming.

WebSocket

Дуплексный канал поверх TCP. Real-time: чат, игры, уведомления.

3. DNS

Иерархия DNS

Domain Name System — распределённая система имён, преобразующая доменные имена в IP-адреса:

$$\text{www.example.com} \xrightarrow{\text{DNS}} \text{93.184.216.34}$$

Кэширование: browser → OS → resolver → root → TLD → authoritative.

Утверждение 4: Кэширование DNS и TTL

Время разрешения имени при кэшировании:

$$T_{\text{DNS}} = \begin{cases} T_{\text{cache}} & \text{if cached (TTL > 0)} \\ T_{\text{recursive}} & \text{if not cached} \end{cases}$$

где $T_{\text{cache}} < 1$ мс, $T_{\text{recursive}} \approx 50\text{–}200$ мс. TTL (Time To Live) определяет время жизни записи в кэше (обычно 300–86400 сек).

4. Маршрутизация

Протоколы маршрутизации

OSPF

Внутри автономной системы (AS). Дijkstra. Государственный протокол.

BGP

Между AS (интернет). Вектор расстояний. Policy-based.

RIP

Малые сети. Макс. 15 хопов. Устаревший.

IS-IS

Линейная квадратичная. Крупные ISP. Быстрее OSPF.

Утверждение 5: Алгоритм Дейкстры для маршрутизации

Кратчайший путь от источника $s$ до узла $v$ в графе $G = (V, E)$ с весами $w$:

$$d(v) = \min_{u \in V} \left( d(u) + w(u, v) \right)$$

Сложность: $O(|V|^2)$ для матрицы, $O((|V| + |E|) \log |V|)$ с кучей. OSPF вычисляет таблицы маршрутизации за $O(n \log n)$ для типичных сетей.

NAT и IPv4 vs IPv6

NAT (Network Address Translation) — трансляция адресов, позволяющая нескольким устройствам использовать один публичный IP:

$$\text{Private} \xrightarrow{\text{NAT}} \text{Public}: 192.168.1.x \to 203.0.113.x$$

IPv6 решает проблему нехватки адресов: $2^{128} \approx 3.4 \times 10^{38}$ адресов (vs $2^{32} \approx 4.3 \times 10^9$ в IPv4).

5. Безопасность сетей

Криптографические протоколы

Утверждение 6: TLS 1.3 Handshake

TLS 1.3 сокращает handshake до 1-RTT (vs 2-RTT в TLS 1.2):

Client → Server:  ClientHello (key_share, supported_versions)
Server → Client:  ServerHello + EncryptedExtensions + Certificate + Finished
Client → Server:  Finished + [application data]
--- 1-RTT, зашифровано ---

0-RTT (early data) при повторном подключении: $T_{\text{resumption}} = 0 \cdot RTT$, но с ограничениями (replay attacks).

Утверждение 7: Энтропия пароля

Энтропия пароля длины $L$ из алфавита размера $|\Sigma|$:

$$H = L \cdot \log_2 |\Sigma| \quad [\text{бит}]$$

Для 12-символьного пароля из 95 печатных символов: $H = 12 \cdot \log_2 95 \approx 78.8$ бит. Скорость перебора GPU: $10^{10}$ хешей/сек → время полного перебора $2^{78.8}/10^{10} \approx 10^{13.7}$ сек $\approx 4 \times 10^5$ лет.

6. Блокчейн и P2P-сети

Блокчейн

Утверждение 8: Цепочка хешей

Блок $B_i$ содержит хеш предыдущего блока:

$$B_i = \text{Hash}(B_{i-1} \| \text{data}_i \| \text{nonce}_i)$$

Proof of Work: Найти nonce такое, что $\text{Hash}(B_i) < \text{target}$. Сложность: $E[\text{attempts}] = 2^{d}$, где $d$ — целевое число бит. Для Bitcoin $d \approx 75$ (2025).

P2P-протоколы

BitTorrent: сегментация файла на $N$ частей. Каждый узел загружает уникальные сегменты. Пропускная способность группы:

$$T_{\text{swarm}} = \min\left(N \cdot T_{\text{upload}}, \sum_{i} T_{\text{download},i}\right)$$

Утверждение 9: DHT (Distributed Hash Table)

Kademlia DHT: поиск за $O(\log N)$ хопов. Каждый узел хранит $k$ ближайших соседей. Вероятность нахождения узла за $h$ хопов:

$$P(\text{found in } h) \geq 1 - \left(1 - \frac{k}{N}\right)^h$$

При $k = 16$, $N = 10^6$: $P > 0.99$ за $h \approx 6 \cdot \log_2 N \approx 120$ хопов.

7. CDN и оптимизация

Content Delivery Network

Утверждение 10: Ускорение через CDN

Время доставки с CDN и без:

$$T_{\text{CDN}} = T_{\text{DNS}} + T_{\text{TCP}} + T_{\text{TLS}} + \frac{S}{B_{\text{edge}}}$$
$$T_{\text{direct}} = T_{\text{DNS}} + T_{\text{TCP}} + T_{\text{TLS}} + \frac{S}{B_{\text{origin}}} + 2 \cdot d_{\text{propagation}}$$

где $S$ — размер объекта, $B_{\text{edge}}$ — полоса от CDN-edge, $B_{\text{origin}}$ — полоса от origin, $d_{\text{propagation}}$ — задержка распространения. Ускорение: $T_{\text{direct}}/T_{\text{CDN}} \approx 5\text{–}20\times$.

8. Резюме главы

Компьютерные сети и интернет — основа современной цифровой инфраструктуры:

  • TCP/IP обеспечивает надёжную доставку пакетов (4 уровня, Shannon limit)
  • HTTP/2 и HTTP/3 оптимизируют загрузку веб-страниц (мультиплексирование)
  • DNS — распределённая система имён с кэшированием
  • Маршрутизация (BGP, OSPF) направляет трафик через интернет
  • TLS 1.3 обеспечивает безопасность (1-RTT handshake)
  • Блокчейн и P2P — децентрализованные сети (PoW, DHT)
  • CDN ускоряет доставку контента в 5–20 раз
